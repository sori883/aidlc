実装済み・検証済み

AI-DLCのHTMLを
読みやすくする実装内容

HTMLを「見出しと箇条書きの置き場」から、 初めて見る人でも判断しやすい説明ページへ変えます。

結論 Coreが作る正式な確認ページと、Agentが作る補足説明を分けます。 どちらも同じ読みやすさの基準を使います。

実装は2本立てです

1. Coreの正式なHTML

承認や確認に使うページです。Goの共通テンプレートから必ず同じ品質で生成します。

対象: ST-04、ST-05、ST-07、ST-08、ST-09、人間の最終確認

2. Agentの補足HTML

人から「わかりやすく説明して」と頼まれた場合だけ、専用SkillとAgentを使います。

対象: 初心者向けの説明、流れの解説、計画の紹介

正式な確認ページができる流れ

正しい情報を保ったまま、見せ方だけをわかりやすくします。

  1. 正本データ 要件、計画、結果、SHA-256など
  2. Goで安全に変換 html/templateでHTML化
  3. 共通デザイン 要点、詳細、判断事項を整理
  4. 人が確認 会話を知らなくても判断できる

新しいHTMLの見え方

最初に結論を示し、細かい技術情報は後から確認できる構成にしました。

例: ST-07 実装結果の確認

「完成したものを公開候補にしてよいか」を確認するページです。

今回の要点 何が完成したか
人が見る場所 画面や操作の確認項目
次の判断 承認か、修正依頼か
要件IDや検証結果など、技術的な詳細を見る

省略はしません。必要な人が開いて確認できるようにします。

テンプレートでトークンを節約します

固定する部分

HTMLとCSSの基本形

余白、色、カード、スマートフォン対応、印刷対応をテンプレートへ入れます。

毎回作る部分

その時に必要な説明

Agentはタイトル、要点、確認事項などの本文を中心に作ります。

テンプレートは explanatory-html Skillの assets/ に同梱しました。

どのAgentが使うのか

  • 初心者向けHTMLが必要な仕事では、専用の explanatory_html_writer が使います。
  • ほかのAgentも、HTML説明が担当範囲に含まれる場合だけSkillを利用できます。
  • 通常の要件整理、設計、実装では、このSkillを使わせません。

つまり、すべてのAgentへ余計なHTML作業を増やす実装にはしません。

変えないもの

  • Coreが管理する要件、状態、監査記録、SHA-256の意味は変えません。
  • Agentの補足HTMLで、正式なCoreレビューを置き換えません。
  • 外部Go moduleや外部Webサービスは追加しません。
  • ai-dlc-test に残る過去の成果物は書き換えません。
