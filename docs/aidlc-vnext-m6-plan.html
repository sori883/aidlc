4つの代表シナリオを通します。

SCENARIO A

小さな文字変更

1 Repository、1 Boltです。必要な確認は省かず、不要な新規設計を作らない短い経路を確認します。

SCENARIO B

依存関係のある機能

複数Boltまたは複数Repositoryです。DAG順序、統合、ST-07の不具合差戻し、修正版の再承認を確認します。

SCENARIO C

実装を伴わない仮説検証

調査や設計のIntentです。BuildやReleaseが該当しなくても、根拠を残してST-09まで進むことを確認します。

SCENARIO D

Releaseと復旧

外部作用はローカルの安全な模擬Targetで試します。drift、失敗、rollback、中断後の再開を確認します。

4シナリオを全配布形式で何度も重複実行はしません。開発Runtimeで全分岐を通し、Codex Bundleとnative版では重要な接続点を代表実行します。

小さな変更でも、AIがStageを飛ばすわけではありません。
