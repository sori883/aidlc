AI-DLC vNext / M5 / ST-09 PLAN

「作った」で終わらず、「狙った結果」を確認する。

ST-09 Outcome Evaluationは、最初に決めた成功条件と、Release後に観測した事実を比較してIntentを閉じる最後のStageです。AIはEvidenceを整理できます。Coreが不足、矛盾、鮮度を検査し、価値判断だけを人間へ返します。

開始点ST-08の確定結果
比較対象約束 vs 事実
最終状態Intent completed
次のStageなし

ST-09が答える質問は一つです。

最初の約束

何を成功とするか

Intent Definitionの期待結果、成功signal、Requirements、承認済み受入条件です。

⇄
最後の事実

実際に何が起きたか

Release Current、Receipt、Deployment Map、観測Evidence、人間の確認結果です。

ST-09は実装の合格試験をやり直すStageではありません。ST-06とST-07は「正しく作れたか」、ST-09は「目的を達成したか」を扱います。

Release結果ごとに、見るものが変わります。

RELEASED

利用後の結果を見る

正式Targetのrevision、健康状態、利用結果、成功signalをEvidenceで確認します。

ROLLED BACK

成功扱いにしない

安全に戻った事実を記録します。目的達成は自動で主張せず、人間へ次の判断を返します。

NOT APPLICABLE

Releaseなしでも評価する

文書、調査、設計などは上流Evidenceと人間確認で成功条件を評価します。

ST-08がnot_applicableでも、ST-09は省略しません。すべてのIntentに「結果」と「終了理由」を残します。

観測は、待つ必要がある場合があります。

1 / CORE確認項目を固定

すべての成功signalに安定IDを付け、漏れを禁止します。

→
2 / OBSERVEEvidenceを集める

任意shellではなく、登録済み方法か人間確認を使います。

→
3 / WAIT OR ASK必要ならparked

観測時刻前や価値判断待ちは、ST-09のまま安全に停止します。

→
4 / EVALUATE事実を比較

全項目を評価し、完了または人間判断へ進みます。

Core自身が長時間sleepしません。`not_before`と期限をStateへ保存し、Evidenceが揃った後の`next`で同じ位置から再開します。

全体評価は4種類です。

ACHIEVED必要な成功条件がすべてEvidence付きで満たされています。
PARTIALLY ACHIEVED一部は達成しましたが、未達項目があります。
NOT ACHIEVED必須条件を満たしていない、またはrollback結果です。
INCONCLUSIVEEvidence不足、観測期限未到来、外部状態不明です。
全必須条件がCore検証済みEvidenceで合格した場合は、追加承認なしでcompletedにできます。それ以外は、人間が終了、観測継続、Follow-up準備を決めます。

人間が決めるのは、価値判断だけです。

continue-observation

まだ判断せず、期限と必要Evidenceを固定してST-09に留まります。

complete-with-outcome

部分達成、未達、不明をそのまま受け入れ、理由付きでIntentを閉じます。

complete-and-draft-follow-up

現在のIntentを閉じ、次のDesign Brief案を作ります。新Intentの作成は別の明示操作です。

ST-09からST-03やST-06へ戻るedgeは追加しません。Release後に見つかった改善は、新しいIntentとして始めます。

Stageの3方式。

EXECUTE

新しく結果を評価

通常はこちらです。Work Request、Evidence、Evaluation、Currentを作ります。

REUSE

同じ評価を厳格に再利用

成功条件、Release Current、Policy、Evidence、鮮度が完全一致する場合だけです。

NOT APPLICABLE

採用しません

Intentには必ず終了結果が必要です。ReleaseなしでもOutcomeは記録します。

提案：はい。

提案：はい。
