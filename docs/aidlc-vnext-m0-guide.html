Milestone 0

作る前に、使える部品を見分ける。

M0は実装の準備です。今ある仕組みを調べ、vNextで使うものと交換するものを決めます。

● M0では、まだ10 Stageを実装しません。
M0の役割
現在の実装 動く部品と古い設計が一緒にある
→
vNextの材料 使う部品と交換する部品が明確

M0で行う5つのこと

現在地を確認し、迷わずM1へ進める状態を作ります。

  1. 01

    現在の健康状態を確認

    TypeScript、Graph、文書、testが正常かを調べます。

  2. 02

    32 Stageの知識を棚卸し

    回収、統合、削除を判断し、足りない能力は新しく設計します。

  3. 03

    部品を4種類に仕分け

    そのまま使う、直して使う、交換する、削除するに分けます。

  4. 04

    変更する場所を特定

    どのファイルと仕組みをM1以降で変更するかを決めます。

  5. 05

    人間が内容を確認

    仕分けと変更範囲を確認し、M1へ進むかを判断します。

何を仕分けるのか

コードを全部捨てません。役割ごとに判断します。

現在のv2実装

実行エンジンと古いWorkflow定義を、一つずつ見分けます。

そのまま使う Bun、TypeScript、Installer、Harnessの基盤です。
直して使う State、Audit、Doctor、Loaderなどの実行機構です。
交換する 32 Stage、Scope Grid、Stage遷移です。
削除する vNextで不要になるv2専用の定義と分岐です。

M0でできあがるもの

M1の詳細設計を始めるための、4つの判断材料です。

A

Baseline結果

変更前のシステムが正常だったことを残します。

B

回収・新規作成Map

古い知識の回収先と、vNextで新しく作る能力を示します。

C

変更境界の一覧

M1以降で触る場所と、再利用する場所を明確にします。

D

進行制御の原則

固定Stage、Coreの決定権、小さな変更の通過方法を明確にします。

M0 Complete

この4点が揃ったらM0完了です。

人間が内容を確認したあと、M1で共通Stage ContractとCoreの権限境界を設計します。

  • ✓現在の正常状態が記録されている
  • ✓回収・削除・新規作成が説明できる
  • ✓M1で変える場所が特定されている
  • ✓AI、Core、人間の進行権限が決まっている
M0では、まだ行わないこと
  • vNextの10 Stageをコードへ追加しません。
  • ST-00 Bootstrapの詳細仕様を確定しません。
  • AIの自律ループを実装しません。
  • 既存のプロジェクトを自動移行しません。
