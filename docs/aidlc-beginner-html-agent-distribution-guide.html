AI-DLCを作る人のためのHTML支援

beginner_html_writerと$beginner-htmlは、 AI-DLCそのものを作るRepositoryの中だけで使う開発支援物です。 AI-DLCを導入したProjectには配布しません。

Repository内だけ AI-DLCを作る側で使います。
正本を守る 説明HTMLは仕様を書き換えません。
配布しない Harnessとdistの境界外です。

何を作ったのか

2つの開発支援物をRepository直下へ置きました。 どちらもAI-DLC本体の機能ではありません。

1

RepositoryローカルのCustom Agent

beginner_html_writerという専用のAIです。

.codex/agents/にあり、このRepositoryで説明HTMLを作ります。

2

RepositoryローカルのSkill

$beginner-htmlという作り方のルールです。

.agents/skills/にあり、短文、図、スマートフォン対応、確認方法を定めます。

3

開発作業の委譲

委譲とは、仕事を専用の担当へ渡すことです。

AI-DLCの開発中に必要なときだけ、親のAIがこのAgentへHTML作業を渡します。

4

配布対象外

Harness、Bundle、導入先Projectには入れません。

AI-DLC利用者向けの機能と、AI-DLC開発者向けの道具を分けています。

人間の依頼からHTML完成まで

この流れは、AI-DLCを作っているRepositoryの中だけで完結します。 導入先Projectでは、このAgentやSkillは利用しません。

AI-DLCの配布経路との境界

AI-DLC本体は、Harnessからdistを通り、導入先Projectへ届きます。 初心者向けHTML helperは、この経路へ入りません。

なぜ一度、配布物と混同したのか

RepositoryローカルのAgentとSkillを、Harness側にもコピーしたためです。 BundleはHarnessに置かれたファイルを配布対象として集めます。

再混入を防ぐテストがあります。 テストは、Harnessにコピーがないことと、導入先向け指示にこのAgentの委譲がないことを確認します。 2つのManifestも、HTML helperを配布一覧へ含めていません。

何を渡し、何が返るのか

専用Agentは、材料が足りないときに想像で補いません。 AI-DLCを作る側で、正本、対象、出力先を確認してから作ります。

入力

Agentへ渡すもの

  • 人間の明示的なHTML作成・修正依頼
  • 現在の正本ファイル、または確定した事実
  • 作成するHTMLの出力先
  • 説明する範囲
  • 修正時は既存HTMLの場所
出力

Agentから返るもの

  • 自己完結した1つのHTML
  • 初心者向けの短い文章
  • 必要な箇所だけの図
  • 使用した正本の一覧
  • 実施した確認と残った制限
  • Repository内のdocs/に置く説明資料

この仕組みが守る境界

説明HTMLは、人間が理解するための補助資料です。 システムを動かす正式な記録でも、利用者へ配るAI-DLC本体でもありません。

行うこと

説明を作る

  • 人間が明示的に頼んだときだけ生成する
  • 正本の意味を変えずに、やさしく説明する
  • 指定されたHTMLだけを作成・修正する
  • 確認できない点を正直に報告する
  • AI-DLCを作るRepositoryの中だけで使う
変更しないもの

正式な記録を守る

  • Runtime
  • Contract
  • State
  • Plan
  • Audit
  • 正本となるJSON
  • Harness、Bundle、導入先Project
HTMLは非正本です。 つまり、HTMLと正本が違う場合は、RuntimeやJSONなどの正本が正しい情報です。
